Jedes Team arbeitet geschützt in seinem Bereich.

Vertrauliche Daten bleiben beim Team, das sie braucht: Granulare Berechtigungen regeln den Zugriff auf Bereiche und Wissensquellen, Guardrails gelten je Bereich. Agent Studio macht eine Maschine für viele Teams nutzbar, ohne dass eines die Daten des anderen sieht.

Berechtigungen

Wer was sieht, ist eine Entscheidung. Keine Nebenwirkung.

Zugriff wird bewusst vergeben, nicht versehentlich geerbt: pro Bereich, pro Wissensquelle, pro Team. Agent Studio setzt diese Entscheidungen durch, auf einer Maschine oder auf vielen.

Bereiche und Wissensquellen

Jedes Team erhält einen eigenen Bereich mit eigenen Wissensquellen. Welche Dokumente, Datenbanken und Ablagen ein Bereich sehen darf, wird granular festgelegt und lässt sich jederzeit prüfen.

Guardrails je Bereich

Was Agenten in einem Bereich dürfen, wird dort festgelegt: welche Quellen sie nutzen, welche Aktionen sie ausführen, wo eine Freigabe nötig ist. Die Regeln eines Bereichs gelten nur für diesen Bereich.

Beispiel

Zwei Teams, eine Maschine, keine Einblicke.

Die Personalabteilung arbeitet mit Gehaltsdaten und Bewerbungen, die Produktentwicklung mit Roadmaps und Konstruktionsunterlagen: beide auf derselben Maschine, ohne die Daten des jeweils anderen zu sehen.

HR-Bereich

Die Agenten im HR-Bereich greifen ausschließlich auf Personalunterlagen zu. Roadmaps, Quellcode und Konstruktionsdaten der Entwicklung existieren für sie nicht: keine Suche, keine Antwort, kein Zugriff.

Bereich Produktentwicklung

Die Entwicklung arbeitet mit ihrem eigenen Wissen, von der Spezifikation bis zum Prototyp. Gehaltsdaten und Bewerbungen bleiben für ihre Agenten unsichtbar, obwohl beide Bereiche auf derselben Hardware laufen.

Eine Maschine. Getrennte Welten.
